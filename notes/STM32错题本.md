## 一、GPIO 与引脚配置

### 1-1 普通推挽和复用推挽搞混

**🔴 必背** ｜ 2026-11-25 ｜ `GPIO_Mode_Out_PP` / `GPIO_Mode_AF_PP`

- **问题**：写 PWM 调光时把 PA0 配成 `GPIO_Mode_Out_PP`，改 CCR 灯亮度毫无变化。
- **涉及代码**：`GPIO_InitTypeDef`、`TIM2_CH1`、`PA0`
- **错误原因**：`Out_PP` 的引脚由**代码**驱动（`GPIO_SetBits`/`ResetBits`）。定时器内部算得再对，比较结果也到不了引脚。
- **解答**：要输出外设波形必须配 `GPIO_Mode_AF_PP`（复用推挽），把引脚交给外设。
- **关键结论**：一个引脚同一时刻只能有一个驱动源。`Out_PP` = 代码管，`AF_PP` = 外设管，**后配置的覆盖先配置的**。
- **复盘要点**：配任何外设前先问一句「这个脚归谁管」，再决定模式。USART 的 TX、SPI 的 SCK/MOSI 同样是 `AF_PP`。

---

### 1-2 结构体填完了，却忘了调用 `GPIO_Init`

**🔴 必背** ｜ 2026-11-25 ｜ `GPIO_Init()`

- **问题**：`GPIO_InitStructure` 的四个成员都赋了值，编译通过，灯不亮。
- **涉及代码**：`GPIO_InitTypeDef`、`GPIO_Init(GPIOA, &GPIO_InitStructure)`
- **错误原因**：结构体只是一个普通变量，**填表不等于提交**。没有 `GPIO_Init()`，硬件完全不知道你要配什么。
- **解答**：每个 `XXXInitTypeDef` 结构体后面必须跟对应的 `XXXInit()` 函数。
- **关键结论**：这条规律通用——`GPIO_InitTypeDef`→`GPIO_Init()`、`TIM_TimeBaseInitTypeDef`→`TIM_TimeBaseInit()`、`TIM_OCInitTypeDef`→`TIM_OC1Init()`、`USART_InitTypeDef`→`USART_Init()`。
- **复盘要点**：写完结构体赋值立刻写 Init 函数，不要隔开。隔开就容易忘。

---

### 1-3 配成复用推挽，但没有配置外设

**🔴 必背** ｜ 2026-11-25 ｜ `AF_PP` + 空定时器

- **问题**：PA0 配成 `GPIO_Mode_AF_PP`，代码里没有一行 TIM2 的配置，灯完全不亮。
- **涉及代码**：`LED.c` 里直接写了 AF_PP
- **错误原因**：`AF_PP` 的语义是「把引脚**交给**外设」。可外设（TIM2）根本不存在，等于门开了没人往里送信号，引脚悬空。
- **解答**：复用推挽必须配套完整的外设配置（开时钟、时基、输出比较、使能），四样缺一不可。
- **关键结论**：**`AF_PP` 不是「自动输出波形」，而是「让位给外设」**。它是通道，不是信号源。
- **复盘要点**：看到 `AF_PP` 就问自己：接管这个脚的外设，配好了吗？

### 1-4 按键输入的三个坑：模式、抖动、边沿

**🔴 必背** ｜ 2026-11-26 ｜ `GPIO_Mode_IPU` / `GPIO_ReadInputDataBit` / 消抖

- **问题**：第一次给呼吸灯加按键，不清楚 GPIO 该配什么模式，以及为什么按一次会跳好几档。
- **涉及代码**：`GPIO_InitTypeDef`、`GPIO_Mode_IPU`、`GPIO_ReadInputDataBit`、`Delay_ms`
- **错误原因**：三个独立问题——① 配成浮空输入（`GPIO_Mode_IN_FLOATING`），引脚没有确定电平，读数随机飘；② 机械按键按下瞬间有 5~20ms 机械抖动，一次按下会被程序读成多次；③ 只判断「当前是不是低电平」，按住不放会连续触发。
- **解答**：
  - 模式用 `GPIO_Mode_IPU`（上拉输入），引脚内部接 3.3V，默认读 1，按键另一端直接接 GND 按下读 0，不需要外部电阻
  - 消抖：读到低电平后 `Delay_ms(20)` 再确认一次
  - 检测「按下瞬间」而不是「按下状态」：记录上一次电平，只在 高→低 的跳变时算一次
- **关键结论**：**读低电平 = 按下**（前提是上拉输入）。如果用下拉输入，逻辑正好反过来。呼吸灯里如果加了 20ms 消抖延时，会让渐变卡顿——这就是后面要改成定时器扫描的原因。
- **复盘要点**：按键代码写完先测「按住不放」——如果档位疯狂上涨，就是没做边沿检测，只看了状态。

---

### 1-5 轮询被阻塞循环饿死：按键要按 1~2 秒才有反应

**🔴 必背** ｜ 2026-11-27 ｜ 轮询 vs 阻塞

- **问题**：按键切档功能，短按完全没反应，必须按住一会儿才生效。
- **涉及代码**：`main.c` 的 `while` 循环 + 两个 `for` 呼吸循环
- **错误原因**：`Key_GetNum()` 是**轮询**——只有程序执行到那一行才会看一眼电平。呼吸的两个 `for` 共 200 步 × `Delay_ms(10)` = **2 秒**，这 2 秒里一次都没检查按键。短按 0.2 秒，正好落在两次检查之间，被完整跳过。
- **解答**：把检测搬进循环内部，每步查一次（配合 `break` 跳出）；根本解法是改用**定时器中断**扫描，让检测与主循环解耦。
- **关键结论**：**轮询的响应延迟 = 两次检测之间的间隔。** 间隔 2 秒，就只能响应按住超过 2 秒的操作。这条规律对串口收数据、ADC 采样、任何轮询式代码都成立。
- **复盘要点**：凡是出现「要按久一点才有反应」，先算两次检测之间隔了多久，不要怀疑硬件。

## 二、时钟与定时器基础

### 2-1 TIM2 在 APB1，GPIO 在 APB2

**🟢 面试/考试** ｜ 2026-11-25 ｜ `RCC_APB1Periph_TIM2`

- **问题**：注释写「//打开定时器」，实际写的是 `RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE)`，开的是 GPIO 时钟。
- **涉及代码**：`RCC_APB1PeriphClockCmd`、`RCC_APB2PeriphClockCmd`
- **错误原因**：TIM2 挂在 **APB1** 总线上，GPIOA 挂在 **APB2**。用错函数不会报错，但定时器没通电。
- **解答**：

```c
RCC_APB1PeriphClockCmd(RCC_APB1Periph_TIM2, ENABLE);   // 定时器
RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);  // 引脚
```

- **关键结论**：TIM2~TIM7 在 APB1；TIM1、TIM8 是高级定时器，在 APB2；所有 GPIO 都在 APB2。
- **复盘要点**：注释写错比代码写错更危险——三天后你会以为自己开过时钟，然后一直找不到为什么不动。

---

### 2-2 PSC 和 ARR 为什么要减 1

**🔴 必背** ｜ 2026-11-25 ｜ `TIM_Prescaler` / `TIM_Period`

- **问题**：直接把 720 和 100 填进去，想知道为什么大家都写 `720 - 1`、`100 - 1`。
- **涉及代码**：`TIM_TimeBaseInitTypeDef`
- **错误原因**：硬件从 **0** 开始数。填 99 是数 0~99 共 100 个数；填 100 会数 101 个。
- **解答**：

```
f = 72MHz ÷ (PSC + 1) ÷ (ARR + 1)
  = 72,000,000 ÷ 720 ÷ 100 = 1kHz
```

- **关键结论**：PSC 决定「数多快」，ARR 决定「数到几归零」，两者相乘决定频率。ARR 还决定亮度档位数（ARR=99 有 100 档）。
- **复盘要点**：频率对不上时，先算这个式子，别靠猜。

## 三、PWM 与输出比较

### 3-1 `TIM_OCStructInit` 为什么必须先调用

**🔴 必背** ｜ 2026-11-25 ｜ `TIM_OCStructInit()`

- **问题**：看教程写「先给所有成员一个默认值，因为有些数值配置不上会随机配置」，不理解这个原因。
- **涉及代码**：`TIM_OCInitTypeDef`、`TIM_OCStructInit(&TIM_OCInitStructure)`
- **错误原因**：**教程那句解释不准确**。真实原因是：函数内的局部结构体变量不会自动清零，拿到的是栈上的残留数据。结构体有七八个成员，只填 4 个，剩下的都是垃圾值。
- **解答**：`TIM_OC1Init()` 会把结构体的**全部成员**都写进寄存器。垃圾值会真的进硬件，导致输出异常、偶发死机。`TIM_OCStructInit()` 先把库预设的安全默认值铺满，再改需要的几格。
- **关键结论**：不是「配置不上会随机」，而是「没填的字段本身就是随机值，而且会一起交上去」。同理 `TIM_TimeBaseStructInit`、`USART_StructInit` 都是这个作用。
- **复盘要点**：凡是用 `InitTypeDef` 的地方，先 `StructInit` 再逐项赋值，是固定套路。

---

### 3-2 `TIM_OCMode` 和 `TIM_OCPolarity` 必须合起来理解

**🔴 必背** ｜ 2026-11-25 ｜ `TIM_OCMode_PWM1` / `TIM_OCPolarity_High`

- **问题**：单独看这两个字段，不知道各自在管什么，也不知道为什么这么配。
- **涉及代码**：`TIM_OCInitTypeDef`
- **错误原因**：这两个是**一对**，一个决定「比完怎么动作」，一个决定「什么算有效电平」，单独记任何一个都没有意义。
- **解答**：

```c
TIM_OCInitStructure.TIM_OCMode     = TIM_OCMode_PWM1;
TIM_OCInitStructure.TIM_OCPolarity = TIM_OCPolarity_High;
```

PWM1 = 向上计数时 `CNT < CCR` 输出**有效**电平；Polarity_High = 有效电平为**高**。合起来就是「数得少时输出高」。

- **关键结论**：CCR 越大 → 高电平越长 → 灯越亮。如果发现**亮度变化方向反了**，不用改逻辑，把 `High` 改成 `Low` 即可（很多开发板 LED 是低电平点亮）。
- **复盘要点**：遇到「能调但方向反」，先查极性；遇到「完全没反应」，先查 `OutputState`。

---

### 3-3 漏掉 `TIM_OutputState_Enable` 会静默失效

**🔴 必背** ｜ 2026-11-25 ｜ `TIM_OutputState_Enable`

- **问题**：时基、输出比较全配对了，灯就是不动，且编译零报错。
- **涉及代码**：`TIM_OCInitStructure.TIM_OutputState`
- **错误原因**：这个字段是「把比较结果**真正接到引脚上**」的开关。不写等于定时器在内部空转，输出被关在门里。
- **解答**：`TIM_OCInitStructure.TIM_OutputState = TIM_OutputState_Enable;`
- **关键结论**：这是最隐蔽的错误之一，因为它**没有任何报错**，只是引脚没输出。
- **复盘要点**：定时器「配置全对但引脚无反应」，按这个顺序查：时钟 → `OutputState` → `TIM_Cmd`。

---

### 3-4 通道号和引脚、函数名必须三者对应

**🟢 面试/考试** ｜ 2026-11-25 ｜ `TIM_OC1Init` / `TIM_SetCompare1`

- **问题**：`TIM_OC1Init` 里的 1 是什么意思，和 `TIM_SetCompare1` 的 1 是不是一回事。
- **涉及代码**：`TIM_OC1Init(TIM2, &结构体)`、`TIM_SetCompare1(TIM2, 50)`
- **错误原因**：不知道 1 是**通道号**，容易用 CH2 却调 `SetCompare1`，改的是另一个通道的值。
- **解答**：TIM2 有 4 个独立通道，每个有自己的 CCR 和引脚：

| 通道 | 默认引脚 | 初始化函数 | 改占空比 |
|---|---|---|---|
| CH1 | PA0 | `TIM_OC1Init` | `TIM_SetCompare1` |
| CH2 | PA1 | `TIM_OC2Init` | `TIM_SetCompare2` |
| CH3 | PA2 | `TIM_OC3Init` | `TIM_SetCompare3` |
| CH4 | PA3 | `TIM_OC4Init` | `TIM_SetCompare4` |

- **关键结论**：通道号、引脚、函数后缀三者必须一致，错一个都不会有输出。
- **复盘要点**：换引脚时（比如从 PA0 改到 PA1），要同时改三处：GPIO 的 Pin、`OCxInit` 的 x、`SetComparex` 的 x。

### 3-5 「输出比较」这个名字的来历

**🟡 了解即可** ｜ 2026-11-25 ｜ 概念

- **问题**：为什么叫输出比较？
- **解答**：核心动作是拿内部计数器和 CCR **比较**，结果往**外**输出。对应的「输入捕获」方向相反——拿外部进来的信号和计数器比，用来测频率和脉宽。
- **关键结论**：理解了命名逻辑，就不会把输入捕获和输出比较搞混。
- **复盘要点**：一个往外出，一个往里进。

### 3-6 配置全对但灯不亮：漏了 `TIM_Cmd`，且主循环没驱动 CCR

**🔴 必背** ｜ 2026-11-26 ｜ `TIM_Cmd(TIM2, ENABLE)`

- **问题**：`LED.c` 里开时钟、配 GPIO、配时基、配输出比较全部写完，编译 `0 Error(s)`，下载后灯不亮，`main` 里只有一个空 `while(1)`。
- **涉及代码**：`Hardware/LED.c` 末尾、`User/main.c`
- **错误原因**：**两个原因叠加**——
  1. 函数最后一句是 `TIM_OC1Init()`，**没有 `TIM_Cmd(TIM2, ENABLE)`**。所有 `Init` 只是把参数写进寄存器，计数器根本还没开始走，PA0 上没有波形。
  2. 就算启动了，`TIM_Pulse = 0` 表示占空比 0%，而 `main` 里没有任何改 CCR 的代码，灯不会自己呼吸。
- **解答**：
  ```c
  TIM_OC1Init(TIM2, &TIM_OCInitStructure);
  TIM_Cmd(TIM2, ENABLE);        // 这一句才是"启动"
  ```
  `main` 里必须有循环连续改 CCR：
  ```c
  for (i = 0; i <= 100; i++) { TIM_SetCompare1(TIM2, i); Delay_ms(10); }
  ```
- **关键结论**：**Init 是"设置"，TIM_Cmd 是"启动"，改 CCR 是"控制"**，三件事缺一不可。初始化只负责让硬件准备好，不负责让它动。
- **复盘要点**：写完定时器初始化，最后检查一遍有没有 `TIM_Cmd`。这是新手第一大漏项，且零报错。

### 3-7 `TIM_SetCompare1` 到底在做什么

**🟢 面试/考试** ｜ 2026-11-26 ｜ `TIM_SetCompare1` / CCR1

- **问题**：不知道这个函数名的含义，也不清楚它在硬件上实际改变了什么。
- **涉及代码**：`TIM_SetCompare1(TIM2, i)`
- **解答**：
  - 名字拆开：`TIM` + `Set` + `Compare` + `1` = 定时器 · 设置 · 比较值 · 通道 1
  - 作用：把 `i` 写进 TIM2 的 **CCR1 寄存器**，等价于直接写寄存器 `TIM2->CCR1 = i;`
  - 它**本身不产生任何输出动作**，只是改了一个数值。真正的波形由硬件比较器拿着 CCR1 和计数器持续比较生成
- **关键结论**：
  - **CPU 只负责设参数，波形由硬件自己维持**。所以主循环里写完就能去干别的，不需要一直盯着
  - Compare 的取值范围是 **0 ~ ARR**。ARR=99 时填 100 已经超过 ARR，输出恒为高电平（100% 占空比）
  - 通道号必须和 `TIM_OC1Init` 的通道一致。对应的读函数是 `TIM_GetCapture1`（输入捕获用，Set/Get 对应写/读）
- **复盘要点**：这个函数是「设目标值」，不是「输出一次」。理解这一点，就理解了外设和 GPIO 电平翻转的本质差别——**前者是设参数让硬件自己跑，后者是 CPU 亲自每一次出力**。

### 3-8 PSC / ARR / CCR 三者的分工

**🔴 必背** ｜ 2026-11-26 ｜ PWM 三个核心参数

- **问题**：呼吸灯跑通了，但仍不清楚 PSC、ARR、CCR 各自管什么，为什么都要减 1。
- **解答**：
  - **PSC（预分频）**：把 72MHz 先分频，决定计数器**每数一个数花多长时间**
  - **ARR（自动重装载值）**：计数器数到它就归零重来，决定**一个周期有多少个数**，同时决定**亮度档位数**
  - **CCR（比较值）**：计数器数到它时输出翻转，决定**高电平占多大比例**
  - 三者都从 **0** 开始数，所以填值都要减 1
- **公式**：
  - 频率 `f = 72MHz ÷ (PSC+1) ÷ (ARR+1)`
  - 占空比 `= CCR ÷ (ARR+1)`
- **关键结论**：PSC 和 ARR 对频率的贡献**在数学上等价**（都在分母），但 **ARR 额外决定分辨率**。同样做到 1kHz，`PSC=719 / ARR=99` 只有 100 档，`PSC=71 / ARR=999` 有 1000 档，后者调光明显更平滑。
- **复盘要点**：调频率 → 改 PSC 或 ARR；调亮度 → 改 CCR；想要更平滑 → **加大 ARR 并相应减小 PSC**（保持两者乘积不变，频率才不会变）。

## 四、工具链与调试

### 4-1 Keil 代码模板引不出来

**🟡 了解即可** ｜ 2026-11-25 ｜ `Templates` / `Ctrl+Shift+Space`

- **问题**：配了模板，打缩写按快捷键没反应。
- **错误原因**：三个可能——① 中文输入法抢了 `Ctrl+Shift+Space`；② 老版本 MDK 用 `Ctrl+Space`；③ 模板建在了错误的文件类型下（如 Text File 而不是 C File）。
- **解答**：先在 Templates 标签页**双击**条目验证模板是否建成功。双击能插入 = 模板没问题，只是快捷键冲突，`Win+Space` 切英文键盘再试。
- **关键结论**：`Ctrl+Space` 是符号补全（补已有名字），`Ctrl+Shift+Space` 是模板插入（生成整段代码），**两个是不同功能**。
- **复盘要点**：真正高频使用的是「符号补全」——`Edit → Configuration → Text Completion` 勾上 `Struct/Class Members`，打点号自动列成员，比模板省事得多。

### 4-3 编译通过但下载报 `Could not load file ...Project.axf`

**🔴 必背** ｜ 2026-11-26 ｜ 工程路径含中文

- **问题**：

  ```
  Error: Flash Download failed - Could not load file
  'C:\Users\LAN\Desktop\stm32\0到1\PWM呼吸灯\Objects\Project.axf'
  ```

  编译日志明明是 `0 Error(s)`、`".\Objects\Project.axf"` 已生成。

- **错误原因**：**路径里有中文**（「0到1」「PWM呼吸灯」）。Keil 编译链接能写出来，但下载器读取 axf 时按非 ASCII 路径解析失败。Keil 对中文、空格路径的支持一直很差，且不同环节表现不一致——这就是「编译过了却下载不了」的原因。
- **解答**：把整个工程文件夹移到**纯英文路径**，例如 `C:\Users\LAN\Desktop\stm32\pwm_led`，删掉旧的 `Objects`、`Listings` 文件夹后重新 Rebuild。

- **复盘要点**：新建工程的第一件事就是定好纯英文路径，不要等出问题再搬。**工程名、文件夹名、路径全都用英文，代码里的注释可以是中文。**

## 五、C 语言语法

### 5-2 `uint8_t i;` 是什么意思，为什么这么写

**🟢 面试/考试** ｜ 2026-11-26 ｜ `uint8_t` / 变量声明位置

- **问题**：`main` 里循环前面写了一句 `uint8_t i;`，不清楚这个类型是什么、为什么不用 `int`、为什么写在函数开头。
- **涉及代码**：`main.c`、`stdint.h`、`stm32f10x.h`
- **解答**：
  - `uint8_t` = **u**nsigned **int**eger **8** **t**ype，无符号 8 位整数，取值 **0~255**，占 **1 字节**
  - `i` 是变量名，这里当循环计数器
  - 写在函数开头，是因为 ARMCC 默认 C90 标准：**变量声明必须放在语句块的最前面**，不能写在中间
- **关键结论**：
  - `uint8_t`/`uint16_t`/`uint32_t` 定义在 `<stdint.h>`，**长度跨平台固定**；`int` 在 STM32 上虽然是 4 字节，但标准不保证
  - 无符号类型做**倒序循环有死循环风险**：`for (i = 100; i >= 0; i--)`，i 减到 0 再减 1 变成 255，条件永远成立 → 卡死
  - 循环变量 `i` 在呼吸灯里**同时充当了 CCR 值**：因为 `ARR+1 = 100`，i 走 0~100 正好对应 0%~100% 占空比。这是巧合——**ARR 改成 999 后，循环必须走 0~999，否则最大占空比只有 100/1000 = 10%，灯会很暗**
- **复盘要点**：无符号变量做循环，条件用 `<=` 或 `!=`，**永远不要用 `>= 0`**。这个坑面试常考。

### 5-3 `static` 让局部变量活过函数返回

**🟢 面试/考试** ｜ 2026-11-27 ｜ `static uint16_t cnt = 0;`

- **问题**：中断函数里的 `static uint16_t cnt = 0;`，不清楚 `static` 在干什么。
- **解答**：
  - **普通局部变量**：进函数时创建，函数返回时销毁，下次进来重新初始化（放在栈上）
  - **`static` 局部变量**：整个程序运行期间**只创建一次**，放在静态存储区，函数返回后值**保留**，下次进来接着用
  - 关键细节：`= 0` 这句**只在第一次执行**，之后再也不执行
- **错误原因（不加会怎样）**：中断每 1 ms 进一次。若 `cnt` 是普通局部变量，每次进来都归零 → `cnt++` 变 1 → 函数返回销毁 → 下次又归零。**永远到不了 500，灯不会变。**
- **关键结论**：**需要「跨调用记住上一次的值」时必须用 `static`**。中断服务函数、状态机、计数器都靠它。
- **复盘要点**：`static` 有两个完全不同的用途，别混——① 修饰**局部变量**：延长生命周期；② 修饰**全局变量或函数**：限制只在**本文件内**可见（如 `static void Delay_ms(...)`）。

### 5-4 三目运算符 `条件 ? A : B`

**🟢 面试/考试** ｜ 2026-11-27 ｜ `? :`

- **问题**：`on ? 100 : 0` 这种写法看不懂。
- **解答**：三段——`条件` 成立取 `A`，不成立取 `B`。`on` 为 1 时给 100，为 0 时给 0。
- **关键结论**：
  - 它是**表达式**，会算出一个**值**，所以能塞进函数参数里；`if/else` 是**语句**，不产生值，不能这么用
  - C 语言判断真假只看一条：**0 是假，非 0 是真**，没有专门的 true/false
  - `on ? 100 : 0` 和 `on * 100` 结果相同，但后者把「亮/灭」和具体数值 100 绑死了，ARR 一改就出错。**用三目，语义清楚**
- **复盘要点**：嵌套调用从最里层往外读——先算三目得到一个数，再把这个数传进函数。

## 六、中断与 NVIC

### 6-1 中断要过两道门：`TIM_ITConfig` 和 NVIC

**🔴 必背** ｜ 2026-11-27 ｜ `TIM_ITConfig` / `NVIC_Init`

- **问题**：不理解为什么中断要配两处，`NVIC_Init` 那一段每行在干什么，优先级数字为什么是 2 和 1。
- **解答**：
  - **第一道门 `TIM_ITConfig`**：外设自己愿不愿举手报信。不开的话，定时器到点了也不吭声
  - **第二道门 `NVIC_Init`**：CPU 的总调度台允不允许它进来。不开的话，外设举手了但 CPU 不理
  - **两道都开，中断才会发生**
- **NVIC 是什么**：Nested Vectored Interrupt Controller，中断总调度台。STM32F103 有 60 个中断源，谁先谁后、能不能打断别人，都归它管。
- **两个优先级数字**：
  - **抢占优先级**（PreemptionPriority）：数字**越小越优先**，高的能**打断**正在执行的低优先级中断
  - **子优先级**（SubPriority）：只在两个中断**同时到达**时决定谁先进，**不能打断**
- **分组在分什么**：`NVIC_PriorityGroup_2` 表示把 4 位优先级切成 **2 位给抢占（0~3）+ 2 位给子优先级（0~3）**。分组改了但数字没跟着改，超出范围会被截断，行为不可预期。
- **关键结论**：
  - `NVIC_PriorityGroupConfig` 整个工程**配一次就够**，重复配无害但没必要
  - 现在只有 TIM2 一个中断，填 2 和 1 其实随便，但**要养成数字小=优先级高的习惯**，以后多个中断才排得清
  - `NVIC_Init` 和 GPI/O、TIM 一个套路：**填结构体 → 调 Init 提交**
- **复盘要点**：中断不响应，按顺序查：① 两道门是否都开；② `TIM2_IRQHandler` 函数名是否和启动文件一致；③ 中断里有没有清标志位。

### 6-2 软件分频：一个 tick 驱动多个任务

**🔴 必背** ｜ 2026-11-27 ｜ `tick % N == 0`

- **问题**：中断每 1 ms 进一次，但呼吸只要 10 ms 一步、按键只要 20 ms 一次，总不能为每个任务各开一个定时器。
- **解答**：让 `tick` 一直累加，各任务用自己的模数取余判断：

  ```c
  static uint16_t tick = 0;

  tick++;                        // 每次进来 +1

  if (tick % 10 == 0) { /* 10ms 任务 */ }
  if (tick % 20 == 0) { /* 20ms 任务 */ }
  if (tick % 100 == 0) { /* 100ms 任务 */ }
  ```

- **关键结论**：
  - **一个硬件节拍可以派生出任意多种节奏**，想加任务就加一个 `if (tick % N == 0)`，不动其他任何东西
  - 不要写成 `if (tick == 10) tick = 0;`——那样 `tick` 一到 10 就清零，`% 20` 永远命中不了。**让 tick 一直往上数，各任务自己取余**
  - `tick` 是 `uint16_t`，65.5 秒回绕一次。回绕不影响节奏，因为取余运算依然连续
- **复盘要点**：主循环里用 `Delay_ms` 排任务，等于把 CPU 按顺序锁死；用 tick 分频，等于让每个任务按自己的节奏走。**这是「阻塞式」到「调度式」的分水岭。**
